# EdgeSync 本地多目标复制内核

固定拓扑：一个主节点（master）+ 两个目标节点（A、B），文件内容实际写入三个本地目录
（`<dir>/objects/v<version>`）。只有主节点接受修改；元数据保存在进程内。

## 使用

```python
from edgesync import SyncKernel, MASTER

k = SyncKernel("data/master", "data/A", "data/B")

v1 = k.put("docs/a.bin", open("a.bin", "rb"))   # 流式写入，返回新版本号
k.delete("docs/a.bin")                           # 逻辑删除，返回是否存在过

k.run_one("A")                                   # 领取并处理 A 的一项待办（可多线程并发调用）
k.run_one("B")

r = k.read("docs/a.bin", "A")                    # node 可为 MASTER/"A"/"B"
r.exists            # 路径是否存在（不存在时其余字段为 None，status 为 "synced"）
r.source_version    # 当前源版本
r.replica_version   # 该节点已发布副本的版本（无副本为 None）
r.stream            # 稳定快照读取流（无副本为 None），用毕必须 close()
r.status            # "synced"：A、B 均已发布当前源版本；否则 "pending"
```

版本号全局单调递增，同一路径删除重建后也不会复用。

## 并发语义

- `put`、`delete`、副本发布各有唯一原子生效点（一把内部锁只保护元数据：指针交换 +
  `os.replace` 原子改名）。输入流读取、文件复制、内容校验全部在锁外分块进行
  （每块 1 MiB，单次传输缓冲远低于 8 MiB 预算，支持 500 MiB 对象），因此某次复制
  暂停时，同路径的 `put`/`delete`/新版本复制以及其他路径的操作都能继续完成。
- 每个已提交版本是不可变对象文件；可读副本逐字节等于其标称版本，不会出现混合版本
  或半个文件。`read` 的元数据与流在同一条临界区内取得，对应同一逻辑时刻。
- 复制任务在领取时和发布时各校验一次“任务版本仍为当前源版本且路径存活”。晚完成的
  旧任务直接丢弃：不会回滚新副本、不会复活已删路径、不会污染删除后重建的路径。
  只有 A、B 都发布了当前源版本，`read` 才报告 `"synced"`。
- `delete` 返回后新发起的 `read` 看到“不存在”（除非路径已重建）；`delete` 之前已取得
  的读取流不受影响，可以读完。
- `read` 永不等待复制队列；副本发布前先完整落地目标文件再更新元数据。

## 资源释放条件

对象文件按引用计数回收。引用来源：存活路径的主节点指针、各目标已发布指针、队列中
及在途的复制任务、打开的读取流。当待办处理完、在途操作结束且读取流关闭后，最后一
个引用归零即删除对应对象文件；过期发布的临时文件立即清理。不靠永久保留历史版本
维持正确性。调用方需关闭取得的每个读取流（支持 `with`）。

## 运行测试

```sh
python3 -m unittest test_edgesync -v
```

测试用 `copy_hook` 中的 `threading.Event`/`Barrier` 构造可控暂停点（不使用 sleep），
覆盖：旧版本复制被暂停时被新版本抢先（A 不回退、B 未追上前整体 pending）、暂停后删除
（重建与不重建两种）、大于缓冲预算的惰性输入在复制与覆盖期间保持快照可读且内存有界。
